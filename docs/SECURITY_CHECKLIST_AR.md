# قائمة الأمان: شو انفحص فعلياً، وشو لا

كل بند تحته اسم الفحص اللي بيتأكد منه بكل دمج (خطوة بمسار جيت هاب، مهمة `image`)، وهو بيشتغل على قاعدة بيانات وريديس وتخزين حقيقيين. ما بنقول «شغّال» لشي ما انجرّب.

## ✅ منفّذ ومفحوص بكل دمج
| البند | كيف مطبّق | الفحص |
|---|---|---|
| عزل المساحات | عمود `workspace_id` بكل جدول + Row-Level Security بقاعدة البيانات + الاتصال بدور بدون صلاحية تجاوز؛ بدون مساحة محددة = ما في صفوف | «الجداول وعزل المساحات»: مساحتين، قراءة وكتابة عبر المساحات مرفوضة |
| كل جدول فيه `workspace_id` عليه عزل | مولّد الهجرات بيضيفه تلقائياً، والفحص بيقارن العدد | نفس الخطوة (المقارنة الديناميكية) |
| الصلاحيات (مالك/محرّر/مشاهد) على كل نقطة بالخادم | سياسات `Member/Editor/Owner`؛ الدور بيُقرأ من القاعدة بكل طلب، فإزالة عضو بتنفذ فوراً | «الدخول والصلاحيات» + كل فحص بيجرّب المشاهد |
| ما في نقطة مكشوفة بالغلط | تدقيق عند الإقلاع بيطفي التطبيق لو نقطة بدون حماية خارج قائمة بيضا (دخول، رجعة OAuth، رابط وسائط موقّع) | «الأمان»: `ENDPOINT AUDIT OK` + كل مسار محمي بدون توكن = 401 |
| تشفير التوكنات والأسرار | AES-256-GCM، مفتاح من البيئة، أعمدة bytea، ما بترجع للواجهة | «ربط فيسبوك وتشفير التوكنات»: ما في توكن نصي بالقاعدة |
| كلمات السر | PBKDF2 (ASP.NET Identity)، 10 أحرف حد أدنى، رسالة موحّدة عند الخطأ | «الدخول والصلاحيات» |
| الجلسات | توكن وصول 15 دقيقة بالذاكرة، توكن تجديد بكوكي httpOnly + Secure + SameSite=Strict، يُستعمل مرة وحدة | «الدخول والصلاحيات» |
| حماية التخمين | حد محاولات لكل إيميل (8 بالدقيقة) + حد للعنوان على مسارات الدخول + حد عام للمستخدم، على ريديس | «الأمان»: 429 مع Retry-After، وإيميل ثاني ما بيتأثر |
| ترويسات الأمان | CSP، `nosniff`، منع الإطارات، `no-store` للـ API، HSTS عبر كادي | «الأمان» (الخلفي والأمامي) |
| السجلات نظيفة | JSON منظّم، المسار بدون استعلام (أكواد OAuth)، ما في توكنات ولا مفاتيح ولا كلمات سر | «الأمان»: بحث عن كل أسرار الفحص بسجلات الخادم والواجهة |
| أسرار بالكود | فحص أنماط (مفاتيح AWS/جيت هاب/OpenAI/مفاتيح خاصة) بأول خطوة | «فحص الأسرار بالكود» |
| إعادة المحاولة وعدم الضياع | كل نشر بالطابور (ريديس)، إعادة بتأجيل متزايد، رفض نهائي لا يُعاد، تنفيذ مكرر آمن | «النشر عبر الطابور» + «بقية المنصات» |
| محتوى الذكاء الاصطناعي | اعتماد بشري قبل النشر أو الجدولة أو الإرفاق؛ التعديل بيلغي الاعتماد | «مركز البرومبتات» + «توليد الصور» |
| وسائط | أنواع وأحجام محددة، معالجة FFmpeg بالعامل، روابط عامة موقّعة ومؤقتة (ساعتين) | «الوسائط» + «بقية المنصات» |
| بروكسيات | بيانات الدخول مشفّرة، عناوين داخلية/محلية ممنوعة، بروكسي ميت = النشر بيفشل بدل ما يطلع مباشر | «الأتمتة» |
| نسخ احتياطي واستعادة | `pg_dump` يومي (+ الوسائط)، واستعادة فعلية على قاعدة ثانية بتتطابق بياناتها | «الأمان» |

## ⚠️ مش مغطّى (قرارات أو أعمال إضافية)
- **المصادقة الثنائية (2FA)** لدخول المستخدمين: غير مبنية.
- **اختبار اختراق خارجي** ومراجعة أمنية بشرية: ما انعملت. اطلب وحدة قبل ما تبيع المنتج لعملاء.
- **المنصات الحقيقية**: الموصّلات مجرّبة على خوادم تجريبية مبنية من التوثيق الرسمي فقط. أول تشغيل حقيقي لكل منصة بدو تطبيق مطوّر وموافقات (راجع `docs/PLATFORMS_AR.md`) وممكن يظهر فرق صغير بالاستجابات الحقيقية.
- **حظر الحسابات**: النشر الآلي على المنصات ممكن يخالف شروطها. استعمل حسابات تملكها، بحدود معقولة، وبمراجعة بشرية.
- **النسخ الاحتياطي خارج السيرفر**: لازم تفعّله بنفسك (راجع دليل النشر).
- **تدوير مفاتيح التشفير**: تغيير `Encryption__Key` بيفقد التوكنات المخزّنة (لازم إعادة ربط الحسابات)؛ ما في أداة تدوير تلقائية بعد.
- **قاعدة بيانات بدور غير مالك**: الاتصال الحالي بمستخدم بصلاحية عالية (يتجاوز RLS) لمسارات الدخول والعمّال بوضع النظام. لو نقلت لخدمة قاعدة بيانات مُدارة، افصل دور التطبيق عن دور الهجرات.
